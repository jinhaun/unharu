# 나다운하루

운하를 배경으로 나의 하루를 기록하는 개인 캘린더입니다.

- 운영 사이트: https://unharu.vercel.app/
- 구성: 정적 HTML/CSS/JavaScript 화면 + Vercel 서버 함수 + Supabase 인증·저장소
- 이 저장소는 2026-10-16 운영 사이트와 같은 상태입니다. 로컬 전용 푸시 알림과 Google 계정 선택 실험은 포함하지 않습니다.
- 기존 주소와 저장소 식별자 `unharu`는 유지합니다. 이름 변경으로 기존 기록을 옮기거나 초기화하지 않습니다.

## 주요 기능

### 일정과 달력
- 일정 입력·날짜별 상세·반복 일정·캘린더 내보내기
- 캘린더 날짜를 누르면 그 날짜의 입력창과 기록을 바로 볼 수 있습니다. 아래쪽 일정 추가는 접기·펼치기를 해도 작성 중인 문장을 지우지 않습니다.
- 같은 날짜는 여행 → 할 일 → 회의 → 소비 → 자격증 → 공유 일정 순으로 묶고, 각 분류 안에서는 시간순으로 보여 줍니다. 시간 미정은 분류의 마지막에 둡니다(달력·날짜 상세·목록 공통). 최근 기록은 입력한 순서를 유지합니다.
- 이미 표시된 기록을 누르면 날짜 상세에서 그 기록을 먼저 보여 줍니다.
- 할 일에 시작·종료 시간을 지정하거나 종료 시간 '잘 모름'을 고를 수 있습니다.
- 남은 할 일은 선택한 달의 오늘 이후 미완료 항목만 셉니다. 지난 기록은 지우지 않습니다.

### 여행
- 입력 종류에서 '여행'을 고르고 마지막 날을 정하면, 시작일부터 마지막 날까지 달력에 한 줄로 이어서 보여 줍니다(예: 2박 3일).
- 여행 기간이 겹치면 줄을 나눠서 서로 가리지 않게 표시합니다.

### 날짜별 사진 (공개 반영 전)
- 달력의 날짜 → **이날 사진** → **사진 선택** 또는 **사진 촬영** → 미리보기 → **선택한 사진 저장**.
- 같은 계정으로 로그인한 휴대폰과 컴퓨터에서 날짜별 사진을 조회·추가·크게 보기·삭제할 수 있도록 구성했습니다. 본인 전용이며 일정 공유·그룹 공유에는 포함되지 않습니다.
- 한 번에 10장, 원본 한 장당 20메가바이트까지. 긴 변 1,600픽셀 이내의 JPEG로 변환해 저장하며 촬영 위치 정보는 보내지 않습니다. 원본은 별도로 보관하세요. HEIC·HEIF는 브라우저가 열 수 있을 때 변환하며, 지원하지 않으면 JPEG로 변환해 선택하라는 안내가 나옵니다.
- 사진은 기존 일정 목록과 별도의 비공개 저장 공간에 한 장씩 추가합니다. 사진 새로고침과 창으로 돌아오기 시 목록을 다시 조회합니다. 선택만 한 사진은 탭을 바꾸거나 창을 닫으면 취소되며, 이미 저장한 사진은 유지됩니다.
- 시험 화면에서는 이 브라우저에만 저장합니다. 실제 계정 저장은 `docs/day-photos-setup.sql`의 비공개 저장 공간 설정과 운영 게시 후 두 기기에서 확인해야 합니다. 아직 운영 저장소 설정·게시를 실행하지 않았습니다.
- 검증(2026-11-12): 사진 관련 신규 검사 15개 통과. 전체 273개 중 268개 통과, 기존 복사본 경로 누락 5개는 그대로입니다. 브라우저에서 시험 그림의 준비·저장·확대·새로고침 유지·날짜 분리·잘못된 형식 차단·10장 제한·선택 취소·삭제 취소·삭제를 확인했습니다. 390픽셀 화면에서 가로 넘침 없음, 사진 선택/촬영 버튼 높이 44픽셀 확인. 실제 휴대폰 카메라·HEIC 변환·두 기기의 계정 동기화는 아직 확인하지 않았습니다.
- 운영 반영 순서: 승인 → 대상 프로젝트와 기존 저장소 접근 규칙 확인 → `docs/day-photos-setup.sql` 적용 → 별도 시험 계정으로 본인 사진 조회·추가·삭제와 다른 계정/비로그인 접근 거절 확인 → 사이트 게시 → 휴대폰과 컴퓨터에서 같은 계정으로 확인. 저장소 설정안은 나다운하루 사진 전용 공간과 그 공간의 접근 규칙만 추가하며 기존 일정·공유 표를 변경하지 않습니다. 이전 구조 변경 파일을 재실행하지 마세요.

### 오늘 도우미
- 에너지와 가용 시간에 맞춰 오늘의 할 일을 추천하고 시작·완료·완료 취소·미루기를 할 수 있습니다. 외부 AI에 기록을 보내지 않는 로컬 규칙 기반 추천입니다.

### 소비
- 소비 카테고리(식비·간식·카페·교통·쇼핑·구독·의료·게임·기타)·필터·월별 소비 비교, 날짜 옆 그날 소비 합계(원 단위). 스팀·닌텐도·카드팩·뱅가드 같은 말은 자동으로 게임으로 나눕니다.
- 소비 분석 화면의 요약 상자: '날짜별'은 돈을 쓴 날마다 합계를 카테고리별 색 조각과 금액(예: 식비 9,000원 · 카페 5,500원)으로 나눠 보여 주고, 날짜를 누르면 그날 기록이 열립니다. '카테고리별'은 그 달의 카테고리 합계와 비율을 보여 주며, 누르면 해당 카테고리 기록만 봅니다.
- 하루 평균 소비: 이번 달은 월초~오늘 소비를 지난 날짜 수로 나눕니다(소비 없는 날 포함, 미래 예약 제외). 지난 달은 그 달 전체 일수 기준, 다음 달은 —로 표시하며 미정·비정상 금액은 빼고 계산합니다.

### 교통
- ODsay 정류장·지하철 검색, 경유지, 귀가 역방향 경로, 자주 가는 경로 저장
- 교통비는 선택한 경로와 환승 조건에 따른 **추정값**일 수 있어 카드의 실제 청구액과 다를 수 있습니다. 실제 결제액으로 고쳐 저장할 수 있습니다.

### 날씨·자격증
- 서울 날씨, 자격증 일정
- 날씨는 기상청 단기예보 조회서비스(공공데이터포털)를 씁니다: 지금 기온·비는 초단기실황(실제 관측), 오늘 최고·최저와 시간별 강수확률은 단기예보. 인증키는 Vercel 환경변수 `KMA_SERVICE_KEY`(Secret)에만 두고 서버 기능 `api/kma-weather.js`가 대신 조회하며, 결과를 10~30분 함께 써서 하루 호출을 약 4천 번으로 줄입니다. 기상청 연결이 안 되면 Open-Meteo로 자동 대체합니다.
- 비 표시는 지금 이후 시간 중 강수확률 30% 이상인 구만 보여 주고, 지금 비가 오는 구는 "지금 비"로 표시합니다.
- 자격증 일정: 시험 검색 → 여러 시험 선택 → 선택한 시험 보기. 처음에는 아무 시험도 선택하지 않으며, 선택은 브라우저·로그인 계정별로 기억합니다(다른 기기로 자동 동기화하지 않음).

- SQLD·TOEIC·JLPT·한국사 심화 일정을 제공합니다. 정보처리기사(공식 일정 재확인 필요)·컴활 1/2급(시험장별 상시)은 공식 안내 링크만 제공하고 임의 날짜를 만들지 않습니다. 2026년 하반기 자료이며 실시간 자동 수집이 아닙니다. 출처와 범위: `docs/exam-settings-v50.md`

### 환율 (공개 반영 전)
- 날씨 아래 **자주 보는 환율**에서 원화 기준 환율을 봅니다. **표시할 통화 선택**을 펼쳐 13개 통화를 켜고 끄며, 선택은 이 브라우저에 자동으로 기억합니다. 기본은 미국 달러·일본 엔·유로입니다. 선택 설정은 기기 사이에서 자동으로 공유하지 않습니다.
- 일본 엔은 100엔, 베트남 동은 1,000동, 나머지는 1단위 기준입니다. 각 통화의 기준일과 최근 조회 시각을 구분해서 표시합니다. 은행 수수료가 포함되지 않은 참고용 기준 환율이며 실시간 거래 가격이 아닙니다.
- `api/exchange-rates.js`가 [Frankfurter 공식 자료](https://frankfurter.dev/)를 인증키 없이 조회합니다. 서버 응답은 1시간 함께 쓰며, 조회 실패 시 이전 조회 자료가 있으면 기준일과 오류 안내를 남깁니다. 일부 통화가 누락되면 해당 통화만 자료 없음으로 표시합니다.
- 시험 화면의 금액은 명시된 예시이며 실제 환율이 아닙니다. 실제 운영 응답은 별도 서버 기능을 포함해 게시한 뒤 확인해야 합니다. 새 저장 공간이나 데이터베이스 설정은 필요 없습니다.
- 검증(2026-11-12): 새 자동 검사 7개 통과, 기존 옛 폴더 누락 검사 5개의 실패는 동일합니다. 실제 공개 응답의 13개 통화 환산과 브라우저 통화 변경·전체 해제·새로고침 후 기억·기본 통화 복원을 확인했습니다. 좁은 화면에서 가로 넘침 없음 확인(시험 브라우저가 요청한 375픽셀 대신 실제 560픽셀로 표시해 375픽셀·실물 휴대폰 확인은 남아 있습니다).

### 로그인과 일정 공유
- Google 로그인, 사용자별 비공개 기록 저장
- 여러 기기에서 써도 기록이 지워지지 않습니다: 저장 직전에 계정의 최신 기록을 읽고 이 기기에서 바뀐 것만 합쳐 저장하며, 화면으로 돌아오거나 1분마다 다른 기기 기록을 불러옵니다. 계정에서 기록을 지우는 것은 삭제 버튼·출퇴근 합치기·자주 가는 경로 삭제뿐입니다(`assets/cloud-merge.js`).
- 개별 일정 공유: 로그인한 나다운하루 사용자가 소유자의 정확한 Google 이메일을 입력하면 공유 일정의 제목·날짜·시간·메모만 읽기 전용으로 볼 수 있습니다.
- 공유 일정(다른 사람 일정·그룹 일정·달력에 함께 보이는 일정)은 오늘부터 다음 주 일요일까지만 요일과 함께 이번 주·다음 주(대한민국 날짜 기준 월~일)로 나눠 보여 줍니다. 오늘보다 지난 날짜와 범위 밖 일정은 지우지 않고 화면에서만 뺍니다.
- 그룹 일정은 사람마다 고정 색(카드 왼쪽 줄·이름표)으로 구분하고, '날짜순'(이번 주·다음 주)과 '사람별'(사람마다 묶음) 보기를 고를 수 있습니다. 사람 이름표를 누르면 그 사람 일정만 숨기거나 다시 보입니다. 보기 방식은 이 브라우저에 기억합니다.
- 조회할 이메일을 즐겨찾기에 '누나' 같은 별칭으로 등록할 수 있습니다(최대 20개, 상대방 권한은 바꾸지 않음). 즐겨찾기는 내 계정에 저장되어 휴대폰·컴퓨터 어디서나 같이 보이며, 공유 일정을 조회해 본 이메일은 자동으로 즐겨찾기에 기억합니다.

> 공유 표시는 기본으로 꺼져 있습니다. 이메일을 아는 로그인 사용자는 공유된 일정을 볼 수 있으므로 민감한 내용은 공유하지 마세요. 받은 사람이 이미 읽거나 복사한 정보는 공유 해제만으로 회수할 수 없습니다.

### 화면과 글꼴
- 기본 글꼴은 나눔스퀘어입니다. 메뉴에서 프리텐다드·나눔스퀘어 네오·수트·원티드 산스·본고딕 중 하나로 바꿀 수 있습니다.
- 고른 글꼴은 Google 계정 정보(`user_metadata.unharu_font`)에 저장돼 다른 기기에서도 따라오고, 빠르게 뜨도록 이 브라우저에도 기억해 둡니다.
- 채용 뉴스레터 메뉴·자료는 앱과 공개 파일에서 뺐습니다. 과거 Git 기록은 바꾸지 않았습니다.

## 실행과 검사

- 검사: Node.js 24에서 별도 설치 없이 `npm test` 또는 `node --test tests/*.test.mjs`. 가상 데이터를 써서 실제 ODsay 검색 횟수를 쓰지 않습니다.
- 내 컴퓨터에서 미리보기: `node tools/preview.mjs` → http://127.0.0.1:4259/?test=x (시험 모드라 로그인 없이 화면을 봅니다. 서버 함수와 외부 API는 부르지 않습니다.)
- Google 로그인은 Supabase의 허용 복귀 주소 설정이, 실제 교통 기능은 서버 함수와 ODsay 등록 도메인이 필요합니다.
- 알려진 문제: 일부 비교 검사(5개)는 예전 버전 폴더 경로를 가리켜서 실패합니다. 앱 기능 문제는 아닙니다.

## 설정과 비밀값

- `assets/supabase-config.js`와 교통 서버 함수에는 운영 프로젝트의 **공개용** Supabase 연결 주소·키만 있습니다(관리자 키 아님). 실제 데이터 접근은 로그인과 행별 권한 정책으로 제한합니다.
- ODsay 비밀값은 Vercel 환경변수 `ODSAY_API_KEY`, `ODSAY_ALLOWED_EMAIL`로만 설정합니다. `.env.example`에는 이름만 있습니다.
- 실제 일정·소비·개인 연락처·인증 토큰·환경변수 값·로컬 백업은 이 저장소에 넣지 않습니다.
- 다른 Supabase 프로젝트에서 실행하려면 공개용 연결 설정과 교통 서버 함수의 인증 주소를 함께 검토해야 합니다. 운영 설정을 임의로 바꾸지 마세요.

## 데이터베이스

- `supabase/migrations/`: 나다운하루 전용 구조 변경 파일 3개(원본 그대로). 운영 저장소에는 이미 적용되어 있으니 다시 실행하지 마세요. 새 환경에서는 날짜순으로 검토하고 Google 인증·복귀 주소·저장 권한을 따로 설정해야 합니다.
- 같은 Supabase 프로젝트를 사주 서비스, 멀리건 랩(`mulligan_` 표)과 함께 씁니다. 다른 서비스의 표는 건드리지 않습니다.
- `tests/*-rls.sql`은 접근 권한 검사용 가상 자료입니다. 격리된 시험 환경에서 전체 트랜잭션을 되돌리는 방식으로만 실행하고, 운영에 직접 실행하지 마세요.

## 배포

- 이 GitHub 저장소는 코드 보관용이며, Vercel 자동 배포와 연결하지 않았습니다. 운영 사이트는 Vercel 프로젝트 `unharu`에 직접 올립니다.
- 올릴 때는 저장소 루트를 쓰고, `.vercelignore`로 시험·구조 파일과 예전 공유 스크립트를 뺍니다. 비밀값은 호스팅 설정에만 둡니다.
- 일정 내보내기는 휴대폰 캘린더로 가져오는 방식이며, 서버 푸시 알림과는 다릅니다.
